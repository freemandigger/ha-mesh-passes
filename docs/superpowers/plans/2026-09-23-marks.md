# Оценки в аддоне «МЭШ: проходы» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Аддон запрашивает оценки ребёнка в МЭШ: пока ребёнок в школе — копит изменения и отдаёт их в событии выхода, в остальное время публикует новые и исправленные оценки отдельным событием «Оценка»; blueprint строят из этого готовые тексты уведомлений.

**Architecture:** Новый метод `MeshClient.marks` и чистый модуль `app/marks.py` (сравнение, схлопывание, сериализация). `PollerState` хранит запомненные оценки и накопленные изменения. `Poller` после проходов каждого ребёнка делает шаг оценок, который никогда не бросает исключений, и распределяет изменения: в событие выхода, в накопление или отдельными событиями. `MqttPublisher` публикует поле `marks` у выхода и новое событие в топик `…/mark`; discovery добавляет сущность `event.mesh_<slug>_mark`.

**Tech Stack:** Python 3.12, asyncio, aiohttp, aiomqtt; pytest + pytest-asyncio + pytest-aiohttp, фейковый mos.ru (`tests/fake_mos.py`); ruff; uv. Для тестов шаблонов blueprint — jinja2 (dev-зависимость).

**Spec:** `docs/superpowers/specs/2026-09-23-marks-design.md` (основная спека аддона — `docs/superpowers/specs/2026-09-16-mesh-passes-addon-design.md`).

## Global Constraints

- Код других проектов не копируется; эндпоинт оценок известен из OctoDiary/OctoDiary-py (MIT) — только благодарность в README.
- В логах нет токенов, cookies, кодов SMS и персональных данных. Про оценки в лог пишется только `Оценка: new|changed, ребёнок <id>`, без предмета и значения.
- Запросы к `school.mos.ru/api` — клиентом без cookie-jar, только `Authorization: Bearer` (иначе 401 «Found multiple bearer tokens»).
- Эндпоинт: `GET /api/family/mobile/v1/marks?student_id=<children[].id>&from=YYYY-MM-DD&to=YYYY-MM-DD`, заголовки `x-mes-subsystem: familymp`, `client-type: diary-mobile`, `profile-id: <profile_id>`.
- Окно оценок — 30 дней: `from = сегодня − 29 дней`, `to = сегодня`; запомненные оценки с датой урока раньше `from` удаляются.
- Опция `marks_interval`: int, минуты, по умолчанию 15, допустимо 0–120, 0 — оценки не запрашиваются, а запомненные и накопленные удаляются. В Docker — `MARKS_INTERVAL`.
- Сущность `event.mesh_<slug>_mark`, `event_types: [new, changed]`, топик `mesh_passes/<account_id>/child/<child_id>/mark`, не retained. Поле `marks` есть только у события выхода.
- Порядок изменений везде: по дате урока, затем по предмету, затем по id.
- Сбой шага оценок никогда не мешает публикации событий проходов и не меняет статус учётной записи.
- Строки для пользователя — по-русски, идентификаторы — по-английски; стиль и плотность комментариев как в окружающем коде (docstring и комментариев почти нет).
- В репозитории нет персональных данных: в тестах вымышленные имена (Иван, Мария), школа и ID.
- Перед каждым коммитом: `uv run ruff check --fix . && uv run ruff format .`, затем `uv run pytest -q` — всё зелёное.
- Коммиты — с email из локального git config репозитория (`616983+freemandigger@users.noreply.github.com`, уже настроен); сообщение заканчивается строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

```python
        if "Cookie" in request.headers or "Auth-Token" in request.headers:
```

```python
from dataclasses import dataclass
from datetime import date, timedelta
from typing import Literal

from app.mesh import Mark

MARKS_DAYS = 30

Known = dict[str, list[str]]


@dataclass(frozen=True)
class MarkChange:
    kind: Literal["new", "changed"]
    mark: Mark
    previous: str | None


def marks_from(today: date) -> date:
    return today - timedelta(days=MARKS_DAYS - 1)


def _order(change: MarkChange) -> tuple[date, str, int]:
    return change.mark.day, change.mark.subject, change.mark.id


def diff_marks(known: Known | None, marks: list[Mark], today: date) -> tuple[list[MarkChange], Known]:
    result = dict(known or {})
    changes = []
    for mark in marks:
        key = str(mark.id)
        old = result.get(key)
        result[key] = [mark.value, mark.day.isoformat()]
        if known is None or (old is not None and old[0] == mark.value):
            continue
        changes.append(MarkChange("new", mark, None) if old is None else MarkChange("changed", mark, old[0]))
    cutoff = marks_from(today).isoformat()
    return sorted(changes, key=_order), {key: item for key, item in result.items() if item[1] >= cutoff}


def merge_held(held: list[MarkChange], changes: list[MarkChange]) -> list[MarkChange]:
    merged = {change.mark.id: change for change in held}
    for change in changes:
        earlier = merged.get(change.mark.id)
        if earlier is None:
            merged[change.mark.id] = change
        elif earlier.kind == "new":
            merged[change.mark.id] = MarkChange("new", change.mark, None)
        elif earlier.previous == change.mark.value:
            del merged[change.mark.id]
        else:
            merged[change.mark.id] = MarkChange("changed", change.mark, earlier.previous)
    return sorted(merged.values(), key=_order)


def change_fields(change: MarkChange) -> dict[str, object]:
    mark = change.mark
    return {
        "subject": mark.subject,
        "value": mark.value,
        "previous": change.previous,
        "date": mark.day.isoformat(),
        "control_form": mark.control_form,
        "weight": mark.weight,
        "is_exam": mark.is_exam,
    }


def change_to_dict(change: MarkChange) -> dict[str, object]:
    return {"kind": change.kind, "id": change.mark.id, **change_fields(change)}


def change_from_dict(data: dict) -> MarkChange:
    kind = data["kind"]
    if kind not in ("new", "changed"):
        raise ValueError(f"неизвестный вид изменения: {kind!r}")
    mark = Mark(
        id=int(data["id"]),
        day=date.fromisoformat(data["date"]),
        subject=str(data["subject"]),
        value=str(data["value"]),
        weight=data.get("weight"),
        control_form=data.get("control_form"),
        is_exam=bool(data.get("is_exam")),
    )
    return MarkChange(kind, mark, data.get("previous"))
```

**Правила шага (спека §4.2) — для проверки реализации:**
1. Проходы ребёнка как сейчас; состояние публикуется.
2. `exit_now` — среди свежих событий есть `exit`.

6. Сначала события проходов (выход — с `marks`, вход — без), потом события «Оценка».

```python
    async def _poll_child(self, child: Child, now: datetime) -> None:
        token = await self._auth.token()
        visits = [
            visit
            for visit in await self._mesh.visits(token, self._auth.profile_id, child, now.date())
            if visit.day == now.date()
        ]
        fresh = self._state.take_new(
            visit_events(child.id, visits), now, timedelta(minutes=self._settings.max_event_age)
        )
        state = child_state(visits, *self._state.last_times(child.id))
        self._state.set_last_times(child.id, state.last_entry, state.last_exit)
        self.child_states[child.id] = state
        await self._publisher.publish_child_state(self._auth.profile_id, child, state)
        exits = [event for event in fresh if event.kind == "exit"]
        changes = await self._check_marks(child, now, bool(exits))
        exit_marks, mark_events = self._route_marks(child, changes, state.at_school, bool(exits))
        for event in fresh:
            _LOGGER.info("Проход: %s, ребёнок %d", event.kind, child.id)
            marks = exit_marks if exits and event is exits[-1] else None
            await self._publisher.publish_event(self._auth.profile_id, child, event, marks)
        for change in mark_events:
            _LOGGER.info("Оценка: %s, ребёнок %d", change.kind, child.id)
            await self._publisher.publish_mark(self._auth.profile_id, child, change)

    async def _check_marks(self, child: Child, now: datetime, exit_now: bool) -> list[MarkChange]:
        interval = timedelta(minutes=self._settings.marks_interval)
        last = self._marks_checked.get(child.id)
        if not interval or not (exit_now or last is None or now - last >= interval):
            return []
        self._marks_checked[child.id] = now
        try:
            marks = await self._fetch_marks(child, now.date())
            changes, known = diff_marks(self._state.known_marks(child.id), marks, now.date())
        except Exception as err:
            if not self._marks_failing:
                self._marks_failing = True
                _LOGGER.warning("Оценки МЭШ недоступны: %s", err if isinstance(err, MeshError) else type(err).__name__)
            return []
        self._state.set_known_marks(child.id, known)
        if self._marks_failing:
            self._marks_failing = False
            _LOGGER.info("Оценки МЭШ снова доступны")
        return changes

    async def _fetch_marks(self, child: Child, today: date) -> list[Mark]:
        profile_id, date_from = self._auth.profile_id, marks_from(today)
        try:
            return await self._mesh.marks(await self._auth.token(), profile_id, child, date_from, today)
        except MeshAuthError:
            return await self._mesh.marks(await self._auth.renew(), profile_id, child, date_from, today)

    def _route_marks(
        self, child: Child, changes: list[MarkChange], at_school: bool, exit_now: bool
    ) -> tuple[list[MarkChange], list[MarkChange]]:
        pending = merge_held(self._state.held_changes(child.id), changes)
        if at_school and not exit_now:
            self._state.set_held(child.id, pending)
            return [], []
        self._state.set_held(child.id, [])
        return (pending, []) if exit_now else ([], pending)
```

Почему `except Exception` в `_check_marks`: события проходов уже отмечены в `state.seen` через `take_new` и публикуются после шага оценок — любое исключение из шага оценок потеряло бы уведомление о выходе (спека §4.2, последний абзац). `asyncio.CancelledError` — `BaseException`, отмену задачи это не глотает.

```yaml
            - label: Оценка исправлена
              value: changed
    skip_marks:
      name: Не показывать отметки
      description: Отметки, о которых не сообщать. «См» — цифровое домашнее задание проверено, «НВ» — не выполнено.
      default:
        - См
      selector:
        select:
          multiple: true
          custom_value: true
          options:
            - См
            - НВ
    actions:
      name: Действия
      selector:
        action: {}

mode: queued

triggers:
  - trigger: state
    entity_id: !input mark_event

variables:
  event_types: !input event_types
  skip_marks: !input skip_marks
  child: "{{ trigger.to_state.attributes.child if trigger.to_state else none }}"
  kind: "{{ trigger.to_state.attributes.event_type if trigger.to_state else none }}"
  subject: "{{ trigger.to_state.attributes.subject if trigger.to_state else none }}"
  value: "{{ trigger.to_state.attributes.value if trigger.to_state else none }}"
  previous: "{{ trigger.to_state.attributes.previous if trigger.to_state else none }}"
  date: "{{ trigger.to_state.attributes.date if trigger.to_state else none }}"
  control_form: "{{ trigger.to_state.attributes.control_form if trigger.to_state else none }}"
  weight: "{{ trigger.to_state.attributes.weight if trigger.to_state else none }}"
  is_exam: "{{ trigger.to_state.attributes.is_exam if trigger.to_state else none }}"
  message: >-
    {%- set notes = ([control_form] if control_form else [])
    + (['за ' ~ date[8:10] ~ '.' ~ date[5:7]] if date and date != now().strftime('%Y-%m-%d') else []) -%}
    {{ '📘 ' ~ child ~ ', ' ~ subject ~ ': ' ~ ((previous ~ ' → ' ~ value) if kind == 'changed' else value)
    ~ ((' (' ~ notes | join(', ') ~ ')') if notes else '') }}

conditions:
  - condition: template
    value_template: >-
      {{ trigger.from_state is not none
         and trigger.to_state is not none
         and trigger.to_state.state not in ['unavailable', 'unknown']
         and trigger.to_state.attributes.event_type in event_types
         and trigger.to_state.attributes.value not in skip_marks
         and (now() - as_datetime(trigger.to_state.state)).total_seconds() < 60 }}

actions: !input actions
```
