# Оценки в аддоне «МЭШ: проходы»

- **Дата:** 2026-09-23
- **Статус:** дизайн согласован
- **Основная спецификация:** [2026-09-16-mesh-passes-addon-design.md](2026-09-16-mesh-passes-addon-design.md) — ссылки вида «осн. §N» ведут в неё.

## 1. Цель и границы

Родитель получает оценки ребёнка вместе с уведомлением о выходе из школы, а оценки, выставленные позже, — отдельными уведомлениями.

**Входит:**

- запрос оценок из МЭШ за последние 30 дней;
- обнаружение новых и исправленных оценок;
- накопление изменений, пока ребёнок в школе, и передача их в событии выхода;
- сущность-событие «Оценка» в HA;
- доработка blueprint «МЭШ: проход ребёнка» и новый blueprint «МЭШ: оценка».

**Не входит:**

- домашние задания, расписание, итоговые оценки, комментарии учителя, удалённые оценки;
- отдельное окно опроса для оценок — используется окно проходов (осн. §6.1);
- продление сессии при старте аддона с протухшим `aupd_token` (§2.2) — отдельная задача.

## 2. Проверенные факты об API

Проверено живым спайком 2026-09-23 на dev-сессии основной разработки (1 ребёнок).

### 2.1. Оценки

`GET https://school.mos.ru/api/family/mobile/v1/marks?student_id=<children[].id>&from=YYYY-MM-DD&to=YYYY-MM-DD`

Заголовки: `Authorization: Bearer <aupd_token>`, `x-mes-subsystem: familymp`, `client-type: diary-mobile`, `profile-id: <profile_id>`. Как и для проходов, без cookie (осн. §2.3). Эндпоинт найден в открытом клиенте OctoDiary/OctoDiary-py (MIT); код не заимствуется.

Ответ (обезличен):

```json
{"payload": [
  {"id": 900001, "date": "2026-09-08", "subject_id": 11, "subject_name": "Математика",
   "value": "4", "weight": 2, "control_form_name": "Контрольная работа",
   "is_exam": true, "is_point": false, "point_date": null,
   "comment": null, "comment_exists": false, "has_files": false, "criteria": null,
   "created_at": "2026-09-10T18:05:00", "updated_at": "2026-09-10T18:05:00",
   "original_grade_system_type": "five",
   "values": [{"name": "5-балльная", "grade_system_type": "five",
               "grade": {"origin": "4", "five": 4.0, "ten": 8.0, "hundred": 75.0}}]}
]}
```

- Оценки отсортированы по дате урока.
- `value` — строка: `"2"`…`"5"`, а также `"См"` (цифровое домашнее задание проверено, почти ежедневно) и `"НВ"` (не выполнено).
- `weight`: 1, у контрольных 2 (`is_exam: true`).
- `date` — дата урока. `created_at`/`updated_at` — без часового пояса; не используются.
- **Оценки выставляют с опозданием:** нередко вечером или через несколько дней после урока — в том числе контрольные и «НВ».

### 2.2. Сессия после недели простоя

Dev-сессия от 16.09 пролежала 7 дней без обращений (`aupd_token` истёк 17.09, `Ltpaexpires` — 16.09):

- `/v2/token/refresh` с просроченным `aupd_token` + `aupd_refresh_token` и с одним `aupd_refresh_token` → `403`. После истечения токена этот путь бесполезен.
- Тихий OAuth через SSO (осн. §2.4) → `302` на callback → новый `aupd_token` на 24 ч. SSO держится минимум неделю простоя — видимо, 30-дневными cookies `login.mos.ru` (`bls`, `cTm`, `cTmTgs`).

Это закрывает осн. §13 Q1. Отсюда же слабость текущей версии: `Auth.load()` требует живой cookie `aupd_token` (просроченный cookie-jar отбрасывает), поэтому аддон, выключенный дольше суток, при старте просит вход, хотя SSO продлил бы сессию. Исправляется отдельно (§1).

## 3. Поведение

### 3.1. Правила

1. **Пока ребёнок в школе** (сенсор «Сейчас» = «В школе», осн. §6.2 п. 4) — новые и исправленные оценки копятся, событий «Оценка» нет.
2. **При выходе** — событие выхода несёт всё накопленное за время в школе плюс изменения, найденные в момент выхода, включая поздние оценки за прошлые дни.
3. **В остальное время** — каждое изменение публикуется отдельным событием «Оценка».
4. **Какие отметки показывать**, решает blueprint (по умолчанию пропускает «См»); аддон публикует все.

### 3.2. Крайние случаи

| Ситуация | Что происходит |
|----------|----------------|
| Вход не зафиксирован (карту не приложили) | аддон считает ребёнка вне школы — оценки идут отдельными событиями сразу |
| Выход не зафиксирован | «В школе» до конца дня; на следующий день (визитов за сегодня нет) накопленное уходит отдельными событиями в первом цикле окна |
| Выход обнаружен позже `max_event_age` | события выхода нет — накопленное уходит отдельными событиями в том же цикле |
| Выход и повторный вход в одном цикле | накопленное уходит с выходом, дальше копится заново |
| Первая проверка оценок ребёнка | все текущие оценки запоминаются молча |
| `marks_interval` = 0 | оценки не запрашиваются; запомненные и накопленные удаляются, при включении — снова молчаливое запоминание |
| Оценку исправили дважды, пока ребёнок в школе | одна запись: для новой — `new` с последним значением; для исправленной — `changed` с исходным `previous` и последним `value`; если значение вернулось к исходному — запись удаляется |

## 4. Устройство

### 4.1. Модули

| Модуль | Изменение |
|--------|-----------|
| `mesh` | dataclass `Mark(id, day, subject, value, weight, control_form, is_exam)`; `MeshClient.marks(token, profile_id, child, date_from, date_to) -> list[Mark]`. Записи без `value` отбрасываются |
| `marks` (новый) | `MarkChange(kind, mark, previous)`; `diff_marks(known, marks, today)` — сравнение с запомненными, слияние, чистка старше 30 дней; `merge_held(held, changes)` — схлопывание по правилу §3.2. Без сети и MQTT |
| `poller_state` | разделы `marks` и `held` в `state.json` |
| `poller` | шаг оценок в цикле ребёнка (§4.2) |
| `publisher` | `publish_event(..., marks)` — поле `marks` у выхода; `publish_mark(...)` — событие «Оценка» |
| `discovery` | компонент `mark` устройства ребёнка |
| `settings` | опция `marks_interval` |

### 4.2. Шаг цикла по ребёнку

Порядок внутри цикла ребёнка (осн. §6.2):

1. Проходы: визиты, состояние, свежие события (как сейчас). Состояние публикуется.
2. `exit_now` — среди свежих событий есть `exit`.
3. **Нужно ли запрашивать оценки:** `marks_interval > 0` и (`exit_now`, или попыток ещё не было с запуска аддона, или с прошлой попытки прошло не меньше `marks_interval` минут).
4. **Запрос:** `marks(from = сегодня − 29 дней, to = сегодня)`.
   - Успех → `changes = diff_marks(...)`.
   - 401/403 → продление (осн. §5) и один повтор. Если продлить не удалось — сбой оценок в этом цикле, а `auth_required` выставит следующий запрос проходов.
   - Сбой (таймаут, 5xx, 429, неожиданный JSON) → `changes = []`, статус учётной записи не меняется, пауза проходов не удлиняется.
5. **Распределение** — в этом порядке:
   - `exit_now` → последнее событие выхода цикла получает `marks = merge_held(held, changes)`; `held` очищается;
   - иначе, если ребёнок в школе → `held = merge_held(held, changes)`;
   - иначе → `merge_held(held, changes)` публикуются отдельными событиями «Оценка»; `held` очищается.
6. Публикация событий проходов (выход — с `marks`), затем событий «Оценка».

События проходов публикуются всегда, даже если шаг оценок упал, — поэтому шаг оценок перехватывает все свои ошибки сам.

### 4.3. Хранение

`state.json` (осн. §3.3) дополняется:

```json
{"marks": {"<child_id>": {"<mark_id>": ["3", "2026-09-16"]}},
 "held":  {"<child_id>": [{"kind": "changed", "id": 900002, "date": "2026-09-17",
                           "subject": "Русский язык", "value": "4", "previous": "НВ",
                           "control_form": "Цифровое домашнее задание", "weight": 1, "is_exam": false}]}}
```

- `marks`: запомненное значение и дата урока. Слияние, а не замена: пустой ответ ничего не стирает. Записи с датой урока раньше `сегодня − 29 дней` удаляются. Нет раздела для ребёнка — первая проверка, запомнить молча.
- `held` не чистится по сроку — уходит по правилам §3.1.
- Старый `state.json` без этих разделов читается без ошибок.

### 4.4. Логи

- `Оценка: new|changed, ребёнок <id>` — INFO, без предмета и значения (как у проходов, осн. §10).
- Сбой оценок — WARNING один раз до восстановления, затем INFO «оценки снова доступны». Без повторов каждые 15 минут.

## 5. MQTT

Новый компонент устройства ребёнка (дополнение к осн. §7.3):

| Компонент | Тип | Источник | Retain |
|-----------|-----|----------|--------|
| Оценка | `event`, `event_types: [new, changed]`, иконка `mdi:notebook-edit` | `mesh_passes/<account_id>/child/<child_id>/mark` | **нет** |

`default_entity_id`: `event.mesh_<slug>_mark`.

Полезная нагрузка события «Оценка»:

```json
{"event_type": "changed", "child": "Иван", "subject": "Математика", "value": "4", "previous": "НВ",
 "date": "2026-09-17", "control_form": "Цифровое домашнее задание", "weight": 1, "is_exam": false}
```

`previous` — `null` у `new`. `control_form`, `weight` — `null`, если МЭШ их не прислал.

Событие выхода (`…/event`) получает поле `marks` — список объектов тех же полей без `event_type` и `child`, но с `kind` (`new`/`changed`). Порядок — по дате урока, затем по предмету. У входа поля `marks` нет.

Неотправленные события «Оценка» при разрыве MQTT ждут в той же очереди, что и проходы (осн. §7.4).

## 6. Blueprints

### 6.1. «МЭШ: проход ребёнка» (`pass_notification.yaml`)

Новые входы:

- `include_marks` — «Добавлять оценки к выходу», boolean, по умолчанию `true`;
- `skip_marks` — «Не показывать отметки», select multiple с `custom_value`, варианты `См`, `НВ`, по умолчанию `[См]`.

Новые переменные:

- `marks` — `marks` события выхода без отметок из `skip_marks`; пустой список для входа или при выключенной галочке;
- `marks_text` — по строке на оценку (формат §6.3), строки через перевод строки;
- `message` — `🏫 <child>: вход в школу|выход из школы в <time>`, а если `marks_text` не пуст — перевод строки и `marks_text`.

Существующие автоматизации продолжают работать: свои тексты не меняются, пока в них не использован `{{ message }}` или `{{ marks_text }}`.

### 6.2. «МЭШ: оценка» (`mark_notification.yaml`) — новый

- **Входы:** `mark_event` (entity, domain `event`); `event_types` (select multiple: «Новая» `new`, «Исправлена» `changed`; по умолчанию обе); `skip_marks` (как в §6.1); `actions`.
- **Триггер:** изменение состояния `mark_event`.
- **Условия:** как в осн. §8.1 (есть `from_state`, состояние не `unavailable`/`unknown`, событие не старше 60 с) плюс `event_type` в `event_types` и `value` не в `skip_marks`.
- **Переменные:** `child`, `kind`, `subject`, `value`, `previous`, `date`, `control_form`, `weight`, `is_exam`, `message` = `📘 <child>, <строка оценки §6.3>`.
- **Режим:** `queued`.

### 6.3. Строка оценки

`<subject>: <оценка>[ (<пояснение>)]`

- `<оценка>` — `value` для `new`; `<previous> → <value>` для `changed`.
- `<пояснение>` — через запятую: `control_form`, если есть; `за ДД.ММ`, если дата урока не «сегодня». «Сегодня» для события выхода — дата выхода, для события «Оценка» — текущая дата HA.
- Скобки не пишутся, если пояснения нет.

Примеры: `Русский язык: 2 (Домашнее задание)`, `Математика: НВ → 4 (Цифровое домашнее задание)`, `Математика: 3 (Контрольная работа, за 16.09)`.

Шаблоны — чистый Jinja плюс `now()`, без фильтров, специфичных для HA, чтобы тесты рендерили их тем же движком.

## 8. Тесты

Без сети, фейковый mos.ru (`tests/fake_mos.py`) получает маршрут оценок с обезличенным ответом формы §2.1.

- **mesh:** параметры `student_id`/`from`/`to`; заголовки `profile-id`, `familymp`, только `Authorization` без cookie; разбор полей, «См»/«НВ», пропуск записей без `value`; 401 → `MeshAuthError`; 5xx/кривой JSON → `MeshApiError`.
- **marks:** первая проверка молча; новая; исправленная; без изменений; пустой ответ не стирает и не даёт лавины; чистка старше 30 дней; схлопывание `merge_held` по §3.2.
- **poller_state:** `marks`/`held` сохраняются и читаются; старый файл без них.
- **poller:** вне школы → событие «Оценка»; в школе → копится; выход → событие выхода с накопленным, `held` пуст; выход запрашивает оценки сразу; сбой оценок при выходе → выход опубликован, статус `ok`, одно предупреждение и строка о восстановлении; протухший выход → отдельные события; нет выхода → накопленное на следующий день; `marks_interval: 0` → запросов оценок нет, состояние очищено; 401 на оценках → продление; двое детей с независимым `held`.
- **discovery, publisher:** компонент `mark`; полезная нагрузка «Оценки»; `marks` в выходе; очередь при разрыве MQTT.
- **settings:** `marks_interval` по умолчанию 15, границы 0–120, `MARKS_INTERVAL` в Docker.
- **blueprints:** структура обоих; рендер `marks_text` и `message` через `jinja2` (с подменой `now()`): новая, исправленная, за прошлый день, пропуск «См», галочка выключена, вход без оценок.

## 10. Риски

| Риск | Смягчение |
|------|-----------|
| Больше запросов к МЭШ | +1 запрос на ребёнка раз в 15 минут и при выходе, только в окне опроса |
| Неизвестные значения `value` («зач», «5-» и т. п.) | показываются как есть; фильтр `skip_marks` принимает свои значения |
| Эндпоинт оценок изменится | сбой оценок не мешает проходам (§4.2), в логе предупреждение |
| Наплыв изменений после долгого перерыва | ограничен 30 днями; при `marks_interval: 0` состояние очищается |
